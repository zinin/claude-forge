Решения ревью итерации 1 (утверждены пользователем, УЖЕ внесены в документы — не «исправлять» обратно):

- **`timeout: 1800000`** у агента — харнес молча клампит к действующему потолку (эмпирически проверено в ревью-сессии: значения выше потолка принимаются без ошибки; на хосте без `BASH_MAX_TIMEOUT_MS` действует 600000). НЕ заменять на 600000.
- **Recovery хирургический**: kill только подтверждённого владельца лока (identity-проверка `ps -fp` против PID reuse); чужие процессы (IDE/другие сессии) — не убивать, спросить пользователя; нет PID в отчёте → только `--stop` + пауза. Blanket-kill отвергнут.
- **Протокол ожидания фоновой сборки**: цикл `sleep 30` → Grep файла вывода по маркерам; бюджет ~20 мин (или ~10 мин без роста вывода) → отчёт INFRASTRUCTURE FAILURE `orphaned background build`.
- **Метки**: в отчёте агента полная строка `run daemon recovery procedure first (see build skill)`; в скилле сознательно короткая `run daemon recovery procedure first` (самоссылка опущена) — это НЕ рассинхрон, семантика префикс-матча зафиксирована в Global Constraints плана.
